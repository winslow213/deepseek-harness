# Agent Note：A2UI 工具分享令牌

Status: implemented

[English](2026-09-10-a2ui-share-tokens.md) | 中文

## 问题

已保存的 A2UI 工具只存在于作者自己的工具库目录中。在团队服务上，每个用户的 runtime 都拥有隔离的 `<harness home>/a2ui-tools/`，因此一个用户创作的工具无法到达队友：除非在消息里重新创作页面并让对方再次导出，否则没有办法把页面从一个工具库搬到另一个工具库。

## 决策

已保存的工具以自包含的承载令牌分享：一个 URL 安全的字符串，携带工具的名称与规范页面，无需服务端存储。接收方导入令牌，其部署重新规范化并持久化该页面。

- **令牌。** `encodeA2uiShareToken(name, page)` 生成 `a2ui-share:<base64url>`，其载荷是带版本的 JSON 信封 `{ v: 1, name, page }`。`decodeA2uiShareToken(token)` 拒绝缺失前缀、空或过大的载荷、无法解码的 base64、非对象载荷、不支持的版本、不安全的名称、缺失页面，以及任何无法通过 `canonicalizeA2uiPage` 的页面。令牌就是导入边界，因此每个字段都会像模型生成的页面一样被重新校验。
- **工具库动词。** `ctx.a2uiStore` 新增 `share(name)`（编码已保存工具）与 `import(token)`（解码并持久化）。Remote 命名空间暴露 `a2uiStore/share` 与 `a2uiStore/import`，未知名称返回 `a2ui-store/not-found`，畸形令牌返回 `a2ui-store/invalid-token`。
- **模型工具。** `a2ui_share(name)` 返回令牌；`a2ui_import(token)` 导入它。二者都不接触会话状态，因此都不要求持有 agent——它们是像侧边栏 list/remove 一样的纯工具库操作。
- **侧边栏。** 每个已保存工具行新增分享按钮，把令牌复制到剪贴板；顶部新增导入输入框，粘贴令牌后重新加载列表。分享/导入文案归 locale 所有。

## 考虑的替代方案

**服务端短令牌。** 把分享存到团队服务并铸造短的不透明令牌。当前拒绝：令牌必须跨隔离的按用户 runtime 存活，而目前没有跨 runtime 存储；自包含令牌无需服务端改动。服务端分享存储可以后续叠加，而不改变导入接口。

**复用 `a2ui_export` 加粘贴导入页。** 拒绝：export 只写本地工具库；它无法把页面移到其他用户，而独立的 share 动词把「为我保存」与「分享给你」两种意图区分开。

**用共享密钥签名令牌。** 拒绝：隔离的 runtime 之间没有共享密钥，且页面本身就是规范化后的声明式文档——与模型生成的页面处于同一信任等级——因此重新规范化（而非签名）才是安全边界。

## 后果

一个工具只需粘贴一个令牌就能从一个用户的工具库搬到另一个用户。令牌是承载值：任何持有它的人都能导入页面，且没有吊销或过期——与复制页面本身具有同样的保密性。导入会替换任何同名工具。令牌被限制为 1 MiB 的编码载荷，永远不会超过模型生成页面本可包含的内容，因此恶意令牌最多只能退化为一次导入失败。
