# Agent Note: open-in-app 客户端侧编辑器启动

Status: implemented

[English](2026-09-08-open-in-app-client-side-editor-launch.md) | 中文

## 问题

open-in-app 的 "Open In..." 按钮通过在主机（运行 dsh 的机器）上派生应用来启动它，这在操作者的浏览器与主机共享同一桌面时是正确的。在远程或 SSH 部署中，操作者的浏览器在另一台机器上，主机派生的编辑器会在无人值守的服务器上打开（或静默地打不开），永远到不了操作者的屏幕。于是按钮看似已安装并返回成功，实际却没有任何可见效果。

## 决定

主机上报自己是否经 SSH 启动，浏览器半边据此把编辑器启动切换到操作者自己的机器上。

- **主机信号。** `GET /open-in-app/apps` 新增必填的 `clientLaunch` 布尔值，取自进程环境中是否存在 `SSH_CONNECTION`/`SSH_TTY`（与 `web-app` bundle 用来抑制默认浏览器打开的启发式一致）。SSH 启动意味着操作者的桌面不在本机。
- **客户端侧启动。** 当 `clientLaunch` 为真时，浏览器半边把编辑器目录 id（`vscode`、`vscodeinsiders`、`cursor`、`windsurf`、`zed`）通过它们的 URL scheme（`vscode://`、`vscode-insiders://`、`cursor://`、`windsurf://`、`zed://`）打开，即把 scheme 赋给 `location.href`，交给操作者系统的协议处理器。没有 scheme 的应用仍走主机启动。
- **不带 workspace 目录。** 深链只打开应用本身。操作者的机器与主机文件系统不同，主机的 workspace 目录无法传递过去；只存在于主机上的目录否则会解析成 "找不到" 的窗口。

## 考虑过的替代方案

**客户端侧 origin 启发式。** 根据页面 origin 是否为回环地址来判定远程与否。否决：SSH 端口转发下页面在 `localhost` 上提供，会被当作本地而仍然主机启动。

**在浏览器插件上加配置开关。** 用 `cordis.yml` 字段门控客户端侧启动。否决：本仓库的浏览器插件不带 `Config` schema，且主机已经采样过一次启动环境，配置标志会重复一个主机可直接上报的事实。

**启动失败后回退。** 保留主机启动，出错时再切换。否决：无头环境下编辑器启动通常"成功"——子进程活过看护窗口即计为已启动——却没有任何窗口，因此没有可回退的失败。

## 后果

远程部署得到了一个可用的编辑器按钮；启动只打开编辑器本身而不带 workspace 目录，因为操作者的文件系统无法命名它。apps 路由载荷新增了一个必填字段，经共享子路径与浏览器半边保持一致。SSH 启发式在 `web-app` bundle 已存在之处重复出现，与既有先例一致，而非为一行环境检查做集中化。
